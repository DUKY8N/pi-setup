코드의 가독성을 리뷰해줘.

리뷰 범위:
$ARGUMENTS

리뷰 범위가 제공되지 않은 경우:
- 먼저 `git status`를 확인해줘.
- staged 변경사항이 있으면 `git diff --cached`를 우선 리뷰해줘.
- staged 변경사항이 없으면 unstaged 변경사항을 `git diff`로 리뷰해줘.
- 변경사항이 없으면 리뷰할 파일, 함수, 또는 범위를 요청해줘.

리뷰 기준:
- 코드 흐름이 자연스럽고 따라가기 쉬운지 확인해줘.
- 조건문, 반복문, 중첩 구조가 불필요하게 복잡하지 않은지 확인해줘.
- 함수와 클래스의 책임이 명확한지 확인해줘.
- 중복되거나 장황하거나 소음이 많은 코드가 있는지 확인해줘.
- 읽는 사람이 작성자의 의도를 빠르게 파악할 수 있는지 확인해줘.

규칙:
- 코드를 직접 수정하지 마.
- 평가와 개선 제안만 제공해줘.
- 문제 코드와 개선 예시를 비교할 수 있게 보여줘.
- 예시 코드는 필요한 경우에만 포함해줘.
- 맥락이 부족하면 가정을 짧게 명시해줘.
- 긴 코드를 통째로 다시 쓰지 말고, 핵심 부분만 발췌해줘.
